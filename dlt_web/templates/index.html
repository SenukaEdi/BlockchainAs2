Part 1 · Task 1

Digital Signature Authentication

Select an originating node, enter a new inventory record, and sign it with that node's RSA private key. All other nodes will verify the signature.

New Record RSA SIGN
How It Works INFO

Step 1 — RSA key components are derived: n = p×q, φ(n) = (p−1)(q−1), d = e⁻¹ mod φ(n)

Step 2 — Record string is SHA-256 hashed, reduced mod n: H(record)

Step 3 — Signature computed: S = H(record)^d mod n

Step 4 — All nodes verify: S^e mod n == H(record) mod n

Part 1 · Task 2

Consensus Protocol (PBFT)

Enter a record and an existing signature. All inventory nodes vote on whether to accept it. Requires 75% supermajority.

Consensus Input PBFT
PBFT Phases INFO

Pre-prepare — Leader broadcasts signed record

Prepare — Each node verifies RSA signature independently

Commit — Each node casts ACCEPT or REJECT vote

Decision — ≥75% ACCEPT → record stored at all nodes

Part 2 · Task 3

Multi-Signature Query & Secure Delivery

Query an item's quantity. All nodes jointly sign the result using the Harn identity-based scheme. The PKG encrypts the response with the Procurement Officer's RSA public key.

Query Request HARN MULTI-SIG
Harn Scheme INFO

PKG issues s_i = ID_i^d_pkg mod n_pkg

Each node signs sig_i = (H(m)·r_i + s_i) mod n_pkg

Aggregate S = Σ sig_i mod n_pkg

Verify S == (H(m)·R + Σs_i) mod n_pkg

Encrypt C = M^e_officer mod n_officer
